# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

The OpenHarmony LiteOS Cortex-A kernel: a small POSIX-leaning kernel for Cortex-A targets (default board: Hi3516D V300; QEMU `arm_virt` is the developer target). It is a sub-tree of the larger OpenHarmony source tree — most of the build only works when this directory is checked out under `kernel/liteos_a/` of a full `repo`-synced OH workspace.

## Build & test

Builds run on a remote Linux host (the repo's project-memory marks build/test commands as remote SSH). The OH dev tree on the remote lives at `/mnt/work/openharmony` and `oh_env.sh` sets the toolchain PATH (`prebuilts/clang`, `prebuilts/build-tools`, `prebuilts/python`).

| Goal | Command |
|---|---|
| Full product build (slowest, but always correct) | `ssh 192.168.1.15 'source /mnt/work/openharmony/oh_env.sh && cd /mnt/work/openharmony && hb build -p qemu_small_system_demo --target-cpu arm'` |
| **Kernel-only fast rebuild** (when only `kernel/liteos_a/**` changed — saves 1-3 min) | Run `kernel/liteos_a/build.sh` directly with the same arg vector the GN ACTION uses. After it succeeds, copy `obj/kernel/liteos_a/make_out/liteos{,.bin,.map}` to `out/arm_virt/qemu_small_system_demo/OHOS_Image{,.bin,.map}`. |
| Run on QEMU | `bash vendor/ohemu/qemu_small_system_demo/qemu_run.sh OHOS_Image yes no no "" no no no "" no` (rebuilds `out/smallmmc.img` via losetup+parted+mkfs.vfat — needs sudo) |
| Tests | `make test` (per project-memory). Suites live under `testsuites/unittest/` and run on QEMU/Hi3516. |
| **exFAT regression** (cmocka host + QEMU LTP smoke) | `bash tools/regress/run_all.sh` — runs Wave 1 (cmocka 49 testpoints, ~2s remote) then Wave 2 (QEMU LTP smoke, ~5min). Writes `docs/test/exfat_regression_<ts>.md` and updates `docs/test/exfat_regression_latest.md` symlink. Exit 0 = pass, 1 = test failure, 2 = panic/hang. |

Plain `make` from this directory works only when `los_config.h` etc. have been generated by `hb`/`mksh`. Do **not** try to build `kernel/liteos_a/` standalone with just the make path — that flow is broken upstream.

`ninja -C out/.../qemu_small_system_demo kernel/liteos_a:make` *can* trigger a stale-rule conflict in unrelated subprojects; bypass via `build.sh` direct invocation.

## Two parallel build systems — the #1 footgun

Every source-file or include-path change must be reflected in **both**:
- The relevant `BUILD.gn` (modern OH path; `hb build` uses this)
- The relevant `Makefile` and (sometimes) `tools/build/mk/los_config.mk` (legacy path; `kernel/liteos_a/Makefile` walks `LIB_SUBDIRS` from there)

Adding a new in-tree filesystem is a worked example: needs `fs/<name>/{BUILD.gn, Makefile, Kconfig}`, an entry in `fs/BUILD.gn` deps, an `ifeq ($(LOSCFG_FS_<NAME>), y)` block in `tools/build/mk/los_config.mk` that appends to `LITEOS_BASELIB` and `LIB_SUBDIRS`, plus weaving the include path into `LITEOS_FS_INCLUDE`. The Kconfig symbol must also be set in the product config at `vendor/ohemu/qemu_small_system_demo/kernel_configs/debug.config` for it to be linked.

## Kconfig gating

Every optional feature is gated by an `LOSCFG_*` symbol declared in some `Kconfig`. New code goes inside `#ifdef LOSCFG_<FEATURE>` … `#endif` (the macro prefix `LOSCFG_` is set by `Makefile:71` `export CONFIG_=LOSCFG_`). The set of effective symbols comes from the *product* config (`debug.config`), not from `.config` in this directory.

## Naming, headers, and patterns

- Public kernel API: types `LosXxx`, functions `LOS_Xxx`, errnos `LOS_ERRNO_*`. Declared under `kernel/include/los_*.h`; implemented in `kernel/base/<subsystem>/`.
- Internal helpers: `OsXxx` / `<module>_<verb>_<noun>` lower_snake. Single-module headers go beside their `.c` (or in a sibling `include/` named `los_*_pri.h`).
- VFS-callback identifiers (in `g_<fs>Vops` / `g_<fs>Fops` tables): `Vfs<Fs><Op>` — e.g. `VfsExfatMount`, `VfsExfatLookup`.
- Cross-module headers: `kernel/include/`, `arch/arm/include/`, `fs/include/`, `compat/posix/include/`. Don't bypass them.

## Link-time tables (the "no init function" pattern)

Several subsystems register through linker-section tables built by `los_tables.h::LOS_HAL_TABLE_ENTRY`. **No explicit registration call needed** — adding the entry to the compiled translation unit is enough.

| Macro | Section | Aggregator |
|---|---|---|
| `FSMAP_ENTRY(name, "fsname", ops, …)` | `.liteos.table.fsmap.data` | `g_fsmap[]` (mount lookup-by-name) |
| `SHELLCMD_ENTRY(name, type, "cmd", …)` | `.liteos.table.shellcmd.data` | shell command list |
| Other tables: trace, plugin, etc. | various `.liteos.table.*` | their respective dispatch arrays |

## Syscalls

Adding a syscall (e.g. when musl complains "Unsupported syscall ID: N"):
  * [ ] 
1. Implement `int Sys<Name>(args…)` in the right `syscall/<domain>_syscall.c` (`process_syscall.c`, `fs_syscall.c`, `ipc_syscall.c`, etc.).
2. Add `extern` declaration to `syscall/los_syscall.h`.
3. Add `SYSCALL_HAND_DEF(__NR_<name>, Sys<Name>, <rtype>, ARG_NUM_<n>)` to `syscall/syscall_lookup.h`.

`__NR_*` macros come from musl headers via the sysroot. Use `ARG_NUM_7` for any 64-bit argument, even if `<n>` would otherwise be smaller.

## Filesystem registration

`MountOps.Mount(struct Mount *m, struct Vnode *blk, const void *data)` — second arg is the **block-device vnode**, not a parent dir. `Unmount(struct Mount *m, struct Vnode **blkdriver)` writes back the block driver. Errors: internal code uses positive errno + goto-stack cleanup; final return is `-ret` so VFS sees negative POSIX errno (`-EINVAL`, `-EROFS`, …).

For partition-relative reads use `los_part_read(part_id, …)` — **not** `los_disk_read(disk_id, …)`. The two APIs take indices from different namespaces; mixing them yields "mutex lock failed" because the wrong disk slot is dereferenced.

`/proc/mounts` (`fs/proc/os_adapt/mounts_proc.c`) only emits a line for FS magics in its hardcoded `switch`. A new FS that wants to be visible needs its magic both set in `statfs.f_type` and added to that `switch`.

## QEMU dev workflow gotchas

- `device/qemu/drivers/virtio/virtmmio.c::VirtmmioDiscover` originally had no claim-tracking — successive calls returned the same slot. A claim-bitmap was added; if you wire multiple HDF MMC controllers be aware that the HDF mmc init path doesn't gracefully handle a failed `VirtmmioDiscover` and will null-deref on missing devices.
- `fs/rootfs/los_rootfs.c` ignores the disk MBR; it reads `bootargs` (`rootaddr`, `rootsize`, `useraddr`, `usersize`) and calls `add_mmc_partition` directly. The optional `exfataddr=<bytes>` bootarg (added locally) carves a 4th partition off the end of "userdata".
- LiteOS-A's MBR scanner (`drivers/block/disk/src/disk.c`) supports up to `MAX_PRIMARY_PART_PER_DISK = 4` primary partitions, so don't depend on extended partitions for in-tree FS testing.

## QEMU end-to-end testing recipe (verified for exfat mount)

This is the exact recipe used to validate a freshly-ported FS via remote QEMU. Steps assume remote host `192.168.1.15`, OH workspace `/mnt/work/openharmony`, and a `SUDO_ASKPASS` script (`/tmp/askpass.sh` echoing `$SERVER_PASSWD`) so non-interactive sudo works.

### Host prerequisites

```bash
# Legacy exfat-utils provides mount.exfat-fuse so the dev host (no kernel exfat) can populate p4.
# It conflicts with exfatprogs — swap if needed:
sudo pacman -Rdd --noconfirm exfatprogs && sudo pacman -S --noconfirm exfat-utils
which mkfs.exfat mount.exfat-fuse   # both must resolve
```

`mkfs.exfat` from legacy `exfat-utils` uses `-n LABEL` (not `-L`); `exfatprogs` uses `-L`. Mismatched flag silently fails to format the partition.

### Disk image build (4-partition, 150 MiB)

The kernel maps logical partitions to MMC device nodes 0-indexed:

| Partition | Range | mkfs | Kernel name | Purpose |
|---|---|---|---|---|
| p1 (MBR) | 10–30 MiB | vfat | `/dev/mmcblk0p0` | rootfs (auto-mount `/`) |
| p2 (MBR) | 30–80 MiB | vfat | `/dev/mmcblk0p1` | userfs (auto-mount `/storage`) |
| p3 (MBR) | 80–100 MiB | vfat | `/dev/mmcblk0p2` | userdata (auto-mount `/userdata`) |
| p4 (MBR) | 100 MiB–end | **exfat** | `/dev/mmcblk0p3` | test payload — `mount -t exfat` target |

```bash
SRC=/mnt/work/openharmony/out/arm_virt/qemu_small_system_demo
FLASH=/mnt/work/openharmony/out/smallmmc.img
sudo rm -f $FLASH
dd if=/dev/zero of=$FLASH bs=1M count=150

sudo losetup /dev/loop590 $FLASH
sudo parted -s /dev/loop590 -- mklabel msdos \
    mkpart primary fat32 10MiB  30MiB \
    mkpart primary fat32 30MiB  80MiB \
    mkpart primary fat32 80MiB  100MiB \
    mkpart primary       100MiB -1s

sudo losetup -o 10MiB  /dev/loop591 /dev/loop590 && sudo mkfs.vfat -F 32 /dev/loop591
sudo losetup -o 30MiB  /dev/loop592 /dev/loop590 && sudo mkfs.vfat -F 32 /dev/loop592
sudo losetup -o 80MiB  /dev/loop593 /dev/loop590 && sudo mkfs.vfat -F 32 /dev/loop593
sudo losetup -o 100MiB /dev/loop594 /dev/loop590 && sudo mkfs.exfat -n EXFATSMOKE /dev/loop594
```

### Populate filesystems

p1 and p2 must contain the build's `rootfs/` and `userfs/` content — without this, `/storage` mount fails (errno 13) and the kernel logs `mount rootfs error!`. p4 holds whatever exfat payload the test reads.

```bash
sudo mkdir -p /tmp/p1 /tmp/p2 /tmp/p4
sudo mount /dev/loop591 /tmp/p1 && sudo cp -rf $SRC/rootfs/* /tmp/p1/ && sync && sudo umount /tmp/p1
sudo mount /dev/loop592 /tmp/p2 && sudo cp -rf $SRC/userfs/* /tmp/p2/ 2>/dev/null; sync; sudo umount /tmp/p2 || true
sudo mount -t exfat /dev/loop594 /tmp/p4 && sudo mkdir -p /tmp/p4/etc && \
    sudo cp /etc/{hostname,hosts,os-release} /tmp/p4/etc/ && sync && sudo umount /tmp/p4

for n in 591 592 593 594 590; do sudo losetup -d /dev/loop$n; done
```

### Bootargs (must be NUL-terminated)

The bootargs string must end with a single `\0` byte (not the literal string `\0`). Stored at offset `512K` inside `smallmmc.img`. `printf '\0'` in single-quotes works; `printf '\\0'` does NOT (printf treats `\\` as a literal backslash, then `0` as a literal `0` — emits `\0` two bytes). Use `perl -e 'print chr(0)'` if you don't trust your shell quoting.

```bash
BOOTARGS='bootargs=root=emmc fstype=vfat rootaddr=10M rootsize=20M useraddr=30M usersize=50M exfataddr=100M'
printf '%s\0' "$BOOTARGS" > $SRC/bootargs
sudo dd if=$SRC/bootargs of=$FLASH conv=notrunc seek=512k oflag=seek_bytes
```

`exfataddr=100M` triggers `los_rootfs.c::AddEmmcParts` to split off the 4th partition. Without it, the kernel only adds 3 partitions and `/dev/mmcblk0p3` never exists.

### QEMU launch (single drive, headless)

```bash
qemu-system-arm -M virt,gic-version=2,secure=on -cpu cortex-a7 -smp cpus=1 -m 1G \
    -bios $SRC/OHOS_Image.bin \
    -global virtio-mmio.force-legacy=false -nographic \
    -drive if=none,file=$FLASH,format=raw,id=mmc -device virtio-blk-device,drive=mmc \
    -device virtio-rng-device
```

- Use `-nographic` (not `-display none`); QEMU 11.0+ otherwise opens an unwanted VNC server on `::1:5900` and the kernel's serial output never reaches stdout.
- Strip `-device virtio-gpu-device,xres=…` from the stock `qemu_run.sh` — QEMU 11.0+ removed the legacy MMIO transitional names of those devices and refuses to start.
- Single MMC drive (`smallmmc.img`) is sufficient. The deprecated dual-drive layout (`smallmmc.img` + `exfat32m.img`) was an early prototype.

### Headless test orchestration

QEMU stdin is the kernel's serial input. Drive it via a named pipe; poll the log for `OHOS:/$` to know the shell is up before sending commands.

```bash
LOG=/tmp/qemu_serial.log; FIFO=/tmp/qemu_in
> $LOG; rm -f $FIFO; mkfifo $FIFO
( exec 3<>$FIFO
  qemu-system-arm ... < $FIFO > $LOG 2>&1 ) &
QPID=$!
for i in $(seq 1 60); do grep -q 'OHOS:/' $LOG && break; sleep 1; done

{ printf 'mount -t exfat /dev/mmcblk0p3 /mnt/exfat\n'; sleep 2
  printf 'echo MOUNT_RC=$?\n';                        sleep 0.5
  printf 'mount\n';                                   sleep 1
  printf 'umount /mnt/exfat\n';                       sleep 1
  printf 'echo TEST_DONE_MARKER\n'
} > $FIFO

for i in $(seq 1 60); do grep -q TEST_DONE_MARKER $LOG && break; sleep 1; done
kill -9 $QPID 2>/dev/null
```

### Don't run `qemu_run.sh` after populating

The vendor `qemu_run.sh` rebuilds `smallmmc.img` (and runs `mkfs.vfat` on every partition) when invoked with `rebuild_image=yes`. Either pass `no`, or invoke `qemu-system-arm` directly. A populated p4 is wiped silently if you forget.

### Expected boot noise (benign)

- `warning: /dev/mmcblk0 lost, force umount ret = -6` — `los_disk_deinit` runs before re-init each boot; the umount has nothing to release. Already silenced in the local stash if applied.
- `[ERR] virtio-mmio ID=1/16/18 device not found` — HDF probe walks all virtio slots; only the ones we actually wire up succeed.
- `[ERR][toybox:toybox]Unsupported syscall ID: 256` — should NOT appear after the `SysSetTidAddress` stub is registered (`syscall/syscall_lookup.h::SYSCALL_HAND_DEF(__NR_set_tid_address, ...)`); if it persists, the build is stale.

### Wave A — cmocka host unit tests (49 testpoints, ~2s)

Source: `testsuites/unittest/exfat/`. Tests run on **host** (Linux x86_64 with `libcmocka-dev`), NOT in QEMU. Compiles 5 production source files (`fs/exfat/util/exfat_chksum.c`, `exfat_options.c`, `exfat_upcase.c`, `fs/exfat/exfat_dentry.c`, `exfat_balloc.c`) with stub headers from `host_stubs/` shadowing LiteOS-A headers (`los_typedef.h`, `los_mux.h`, `los_memory.h`, `disk.h`, etc.).

| Component | Purpose |
|---|---|
| `host_stubs/*.h` | Replace LiteOS-A kernel headers; map `LOS_MemAlloc → malloc`, `LosMux → no-op opaque struct`, `PRINT_ERR → fprintf(stderr)`, `securec memcpy_s → libc memcpy + bounds check` |
| `mock_disk.{h,c}` | `los_part_read` / `los_part_write` route to in-RAM image snapshot. `mock_part_write` modifies RAM but **never** writes back to disk file → repeatable image use across tests. `mock_disk_set_read_fail_at(N)` injects -EIO at N-th read |
| `exfat_image_builder.{h,c}` | Synthesize a 6 KiB hand-rolled exFAT image (boot+FAT+3 clusters: root, bitmap, upcase) plus 5 negative-variant generators (bad signature, bad fs_name, no bitmap dentry, corrupt upcase chksum, bitmap too small) — does NOT depend on host having `mkfs.exfat` |
| `test_<subsystem>.c` | One file per TU. 49 testpoints total: chksum 8 / options 18 / dentry 10 / balloc 8 / upcase 5 |
| `Makefile` | gcc/clang + `-DLOSCFG_FS_EXFAT -Ihost_stubs`, links `libcmocka` |

Run on remote (preferred — uniform CI env):
```bash
ssh 192.168.1.15 'cd /mnt/work/openharmony/kernel/liteos_a/testsuites/unittest/exfat && make'
# tail of output: "=== exfat TOTAL FAILURES: 0 ===", exit 0
```

Run locally (Linux/macOS with cmocka):
```bash
cd testsuites/unittest/exfat && make
# brew install cmocka  / sudo apt install libcmocka-dev  / sudo pacman -S cmocka
```

Adding tests for a new stage (e.g., `lookup-v1`):
1. Append `test_lookup.c` cases in cmocka style: `static void test_<name>(void **state)` + entry in `const struct CMUnitTest test_lookup_tests[]`.
2. Add the production `.c` to Makefile `PROD_SRCS`.
3. Add `extern const struct CMUnitTest test_lookup_tests[];` + `run_suite("lookup", ...)` in `main.c`.
4. Re-run `make`. Failure mode (e.g., new helper requires extra libsec stub) usually surfaces in compile, not at runtime.

### Wave B — LTP smoke regression (~3-5min, runs in QEMU)

Driver: `tools/regress/qemu_ltp_run.sh`. Pre-requisite is the LTP cross-compile (next subsection).

### LTP cross-compile (one-time prep on remote)

Statically linked glibc ARM ELFs **don't load** on LiteOS-A (`OsLoadELFSegment` returns OOM on PT_GNU_STACK / glibc-specific segments). Use **dynamic linking against LiteOS-A's musl** instead:

```bash
ssh 192.168.1.15
cd /mnt/work/test
git clone --depth=1 --branch=20240930 https://github.com/linux-test-project/ltp.git   # ~50 MB
cd ltp && make autotools
SYSROOT=/mnt/work/openharmony/out/arm_virt/qemu_small_system_demo/sysroot
./configure --host=arm-liteos-ohos --prefix=/opt/ltp \
    CC=armv7-unknown-linux-ohos-clang AR=llvm-ar STRIP=llvm-strip \
    CFLAGS="-mfloat-abi=softfp -mfpu=neon-vfpv4 -mcpu=cortex-a7 -O2 --sysroot=$SYSROOT" \
    LDFLAGS="-mfloat-abi=softfp -mfpu=neon-vfpv4 -mcpu=cortex-a7 --sysroot=$SYSROOT"
# build only the smoke set
for t in creat/creat01 open/open01 read/read01 write/write01 unlink/unlink05 stat/stat01; do
  make -C testcases/kernel/syscalls/$t -j
done
# verify dynamic
file testcases/kernel/syscalls/{creat/creat01,open/open01,...}   # must say "dynamically linked, interpreter /lib/ld-musl-arm.so.1"
llvm-strip testcases/kernel/syscalls/...
```

Don't pass `-static` — LiteOS-A rootfs already provides `/lib/libc.so` and `/lib/ld-musl-arm.so.1`. Static glibc binaries DO compile (with the linaro `arm-linux-gnueabi-gcc 7.5` toolchain) but won't run; the OHOS `armv7-unknown-linux-ohos-clang` toolchain is the only one that produces LiteOS-A-loadable ELFs.

Pack into `/mnt/work/test/ltp_smoke.tar.gz` (≤ 30 MB). The runner script extracts it into p2 (userfs / `/storage`) at QEMU startup.

### LTP run mechanics (driven by `tools/regress/qemu_ltp_run.sh`)

1. Idempotently rebuild the 4-partition `smallmmc.img` (skips reformat if p2 vfat + p4 exfat are already populated).
2. Idempotently push `ltp_smoke.tar.gz` to p2 + `/etc` payload to p4.
3. Write 98-byte NUL-terminated bootargs at offset 512K.
4. Launch QEMU `-nographic` with single virtio-blk; FIFO drives stdin, log polling reads stdout.
5. Wait for `OHOS:/$` prompt; feed `mount -t exfat /dev/mmcblk0p3 /mnt/exfat && cd /storage/ltp_smoke && sh run_exfat.sh`.
6. Watch log for `panic | Oops | Kernel BUG` (exit 2 immediately if any) and for `LTP_DONE` / `TEST_DONE_MARKER`.
7. Parse `RC=...` lines, emit `LTP_PASS=X LTP_FAIL=Y` summary.

### Lessons learned (don't re-discover)

- **`g_<fs>Vops = { 0 }`** initializing all VnodeOps slots to NULL **panics on umount** (NULL+4 in `VnodePathCacheFree` during VFS `VnodeFreeAll`). Even if reads/lookup are stubbed, `Reclaim` MUST be a real function — VFS reclaim hook is the proper place to release FS-private `inode_info` attached to `vnode->data`. See `fs/exfat/exfat_super.c::VfsExfatReclaim` for the canonical stub.
- **FS code MUST NOT touch the root vnode in `Unmount`**. Mirror `fatfs_umount`: capture `part->dev` before any frees, free `part->part_name` and call `bops->close(*blkdriver)`, but **never** call `VnodeFree(root)` from the FS callback — VFS handles that itself via `VnodeFreeAll`.
- **FS bug debugging stays inside `fs/<name>/`**. `fs/vfs/`, `kernel/`, `syscall/`, `drivers/block/disk/` are common-layer code; modifying them needs explicit user permission. Other FS (fat / jffs2) working = common layer is OK = the bug is in the new FS.
- `bootargs` end-of-string MUST be a single `\0` byte; `printf '\\0'` emits two literal characters and breaks parsing. Use `perl -e 'print chr(0)'` if uncertain.

## Coding-style audit (Layer S)

`fs/exfat/.clang-format` is an **advisory** style anchor. Layer S audit (defined in `.claude/plugins/specfs-port/prompts/style_audit.md`) judges generated code along 6 dimensions: naming / function-complexity / code-layout / memory & libsec / locking / error-path. Output is a JSON `{is_good, score, violations[]}`. Audit runs by default after Layer 1 (compile) and before Layer 2 (build) when generating new FS code via the specfs-port plugin; opt out per session with `--style-off`.

`clang-format --dry-run` output is fed into Layer S's `[AUTO CHECKS]` segment as a HINT only — its whitespace normalization fights the manual multi-space alignment used in `fs/fat/*` and `fs/jffs2/*`, so it's not a hard gate.

Reference: `docs/exfat_style_audit_v1.md` shows a worked example (6/7 stage pass; `super.c::VfsExfatMount=271 lines` flagged as hard violation for v1.1 split).

## Coding rules to honor

- Every `strcpy` / `strncpy` / `memcpy` / `sprintf` must be the libsec `_s` variant (`strncpy_s`, `memcpy_s`, …) — Huawei security-coding policy. Compiler won't catch the bare versions.
- Kernel heap: `LOS_MemAlloc(m_aucSysMem0, sz)` (or `zalloc(sz)` for zeroed). Free with `LOS_MemFree(m_aucSysMem0, ptr)`.
- Locks: `LOS_MuxLock` if the path may sleep, `LOS_SpinLock` otherwise. **Never** sleep while holding a spinlock.
- Logging: `PRINT_ERR` / `PRINT_INFO` / `PRINTK` from `kernel/include/los_printf.h`. No `printf` in kernel context.
- License header: BSD-3-Clause Huawei Device template (see any existing `.c` in `fs/fat/` or `fs/exfat/`). Do **not** paste GPL Linux file headers — the whole tree is BSD-3-Clause.
